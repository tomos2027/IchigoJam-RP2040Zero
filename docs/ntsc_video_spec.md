# ntscv — RP2040 NTSC コンポジット映像出力ライブラリ 仕様書

本書は `src/video/ntscv*` ライブラリの設計仕様を定める。実装は本書および
公開規格 (NTSC / SMPTE 170M)・pico-sdk (BSD-3-Clause) のドキュメントのみを
根拠として行い、既存ドライバのソースコードを参照・流用しない。

## 1. 実装方式と法的位置づけ

- **方式**: PWM 1ビットD/A (10段) + DMAピンポン (lovyan03氏考案の信号生成手法の独自実装。
  手法・アイデアは著作権の保護対象外であり、コードはすべて新規記述)
- **ライセンス**: MIT (本リポジトリ作者)。クレジットとして、
  - PWM+DMAによるNTSC信号生成の着想: @lovyan03氏
  - 機能互換の参照元 (動作仕様の確認用途、コード流用なし): KenKen氏 `rp2040_pwm_ntsc_textgraph`
  をREADME・ソースヘッダに明記する。
- **用途**: 単体の汎用ライブラリとして他プロジェクトでも利用可能。
  本リポジトリでは `src/ntsc/ntsc_compat.h` (薄いshim) 経由で IchigoJam 移植部と接続する。

## 2. 信号仕様 (公開規格からの導出)

### 2.1 クロックとサンプルレート

| 項目 | 値 | 導出 |
|---|---|---|
| システムクロック | 157.5 MHz | PLLで実現可能かつ下記サンプルレートが整数分周で得られる値 (呼び出し側が設定、本ライブラリは確認のみ) |
| PWM周期 | 11サイクル | 157.5MHz ÷ 11 = **14,318,181 Hz** |
| サンプルレート | 14.3181818 MHz | NTSC カラーサブキャリア 3.579545 MHz の **4倍** (1周期4サンプル) |

### 2.2 水平走査線 (908サンプル = 63.42µs)

| 領域 | サンプル位置 | 幅 | 内容 |
|---|---|---|---|
| H同期 | 0–67 | 68 (4.75µs) | レベル0 (同期チップ。規格値4.7µs→67.3→切り上げ68) |
| ブリーズウェイ | 68–75 | 8 | レベル2 (黒/ブランキング) |
| カラーバースト | 76–111 | 36 (9周期) | カラーモードのみ。黒レベル2を中心に±1、位相は −sin (規格: (B−Y)軸から180°) |
| バックポーチ | 112–171 | 60 | レベル2 |
| **有効画素域** | **172–843** | **672** | 後述のモードごとの内容 |
| フロントポーチ | 844–907 | 64 | レベル2 |

※ 908サンプル/ラインはサブキャリア227周期分に相当 (本方式では搬送波はライン間で位相が
交互せず固定)。実機のNTSC TV受像機での同期・色復元は実績済みの構成と同一幾何を採用。

### 2.3 フィールド構造 (262ライン/フィールド、ノンインターレース)

| ライン | 内容 |
|---|---|
| 0–9 (10本) | 垂直同期 (全ラインほぼ同期レベル、末尾68サンプルのみレベル2 = セレーション) |
| 10–35 (26本) | ブランキング (H同期+バースト+黒) |
| 36–251 (**216本**) | **有効映像** (216 = 27行×8 または 24行×9) |
| 252–261 (10本) | ブランキング |

- フレームカウンタ `drawcount` 互換動作: ライン252の内容を用意した時点でフレームシーケンスを+1。
- ラインごとに呼び出されるコールバック (IchigoJamのTICK相当) を設定可能。

### 2.4 PWM出力レベル (10段D/A、外部回路 75Ω+560pF)

| レベル値 | 信号 | 対応 (IRE換算: 約14.3IRE/段) |
|---|---|---|
| 0 | 同期チップ | −40 IRE |
| 1 | バースト負側 | 黒−1 |
| 2 | ブランキング/黒 | 0 IRE |
| 3 | バースト正側 | 黒+1 |
| 9 | 白 | +100 IRE |

### 2.5 色符号化 (パレット → 4位相QAMサンプル)

標準NTSC式から独自に導出する:

- 輝度: `Y = 0.299R + 0.587G + 0.114B` (Q8係数はコンパイル時にマクロで導出)
- 色差: `U = 0.492(B−Y)`, `V = 0.877(R−Y)` (標準のハーフアンプリチュード係数)
- 搬送波位相: サンプルk (k=0..3) の位相 `θk = 90°·k + TRIM`。
  **TRIM = 30°** — 参照回路 (GP3 + 75Ω + 560pF) における PWMゼロ次ホールド+RCフィルタの
  再構成遅延を実測で補正する経験値 (コンパイル時定数 `NTSCV_CHROMA_PHASE_DEG` で調整可)。
- サンプル値: `level(k) = 2 + round((Y·7 + 7·(0.492(B−Y)·sinθk + 0.877(R−Y)·cosθk)) / 256)`
  (レベル0–10にクランプ)
- パレット: **257エントリ×各位相のPWM比較値** (0–255=文字/グラフィック前景色、256=背景色)
- 既定パレット: 0–7 = RGBビット組合せ (青=bit0, 赤=bit1, 緑=bit2)、8–15 = 半輝度、
  16–255 = 白、背景 = 黒

## 3. 表示モード

すべてのモードで有効画素域は 672 サンプル幅 (172–843)。

### 3.1 IJTEXT (IchigoJam互換 32×24 白黒)

| 項目 | 値 |
|---|---|
| 文字数 | 幅32 × 行24 |
| 1文字 | 幅21サンプル × 高さ9走査線 (8ドット/8ラインフォントを引き伸ばし: 9ライン目=8ライン目) |
| ドット幅配分 | 基本各ドット2サンプル + 幅3ドット (j=1,3,4,6,7) に1サンプル追加。追加位置は起動時に `floor(21(j+1)/8)-floor(21j/8)` から計算して1バイトマスク (`ij_extra_mask`) にする (割込み内のテーブル参照を排除し合成を高速化) |
| 属性 | bit7 (0x80) = 反転 / bit6 (0x40) = カーソル (フォントに `cursor_xor` をXOR) |
| 拡大 | `zoom` = 1/2/4/8。VRAM側で1文字をzoom×zoomセルに複製した前提で、各セルがグリフの該当断片 (横: `8>>log2(zoom)`ドット幅 `20>>log2(zoom)`サンプル、縦: グループ内行位置からフォント行をスケーリング) を描画 |

### 3.2 カラーテキスト (42×27、256色+背景色)

- 1文字 = 8ドット×16サンプル (1ドット=2サンプル、文字ごとに搬送波4周期=位相整合)
- 属性バイト = パレット番号。フォントbit=1 → 文字色、bit=0 → 背景色 (パレット256)

### 3.3 カラーグラフィック+テキスト (42×27 + 336×216)

- GVRAM: 1画素1バイトのパレット番号、336×216バイト (走査線ごとに336バイトストライド)
- テキスト (フォントbit=1) をグラフィックの上に重ねる (テキスト優先)
- 1ドット=2サンプル。偶数ドットはパレット位相0–1、奇数ドットは位相2–3

### 3.4 モノクロテキスト (80×27)

- 1文字 = 8サンプル (1ドット1サンプル)、1ライン8サンプル×80 = 640サンプル
- 属性 bit7 (0x80) = 反転。レベルは黒2/白9の2値

### 3.5 テストパターン (独自機能)

`ntscv_test_pattern(p)` で有効映像域を置き換える:

1. SMPTEカラーバー: 白・黄・シアン・緑・マゼンタ・赤・青の7バー (各96サンプル) + 下部グレースケール。色相・飽和度・輝度の目視検証用。**IJモード中でもカラーバーストを自動的に載せる** (色復調の前提)
2. グリッド: 枠+格子線 (白黒)。ジオメトリ・オーバースキャン確認用
3. IJ経路診断画面: render_ijへの入力ソースを3バンドに分けて差し替え、
   実行時の故障箇所を切り分ける (2026-10 通常版黒画面問題の切り分け用)
   - 行0-6: ライブラリ内合成データ (白一色になるはず → render_ij自体の動作確認)
   - 行7/15: **白いセパレータ** (ここが見えなければrender_ij以前の問題)
   - 行8-14: 実フォント+合成コード ('A'のグリフ → フォントポインタ/データ確認)
   - 行16-23: 実TVRAMそのまま (タイトル文字 or "E nn" → TVRAMへのテキスト到達確認)
   - ビルド: `-DNTSCV_BOOT_TESTPATTERN=3`
   
   ※2026-10追記: IJ経路の黒画面原因として、割込み内のフラッシュ依存
   (`.rodata`上のドット幅テーブル読み出し、`__aeabi_idiv`のフラッシュ呼出) を
   排除した: ドット幅テーブルはRAM (.data)、行変換は起動時作成のRAM表
   (`ij_row_of_line`) で割り算を置換。映像割込みパスは原則フラッシュに
   依存しない (memsetのみ例外: 実績により問題なしと判断)。

## 4. メモリインターフェース

ライブラリはVRAMを所有せず、呼び出し側が所有するバッファをバインドする:

- `ntscv_bind_text(codes, attrs, cols, rows)` — 文字コード配列と属性配列
- `ntscv_bind_graph(vram)` — グラフィックVRAM (336×216バイト)
- `ntscv_bind_font(ptr)` — 256文字×8バイトフォント (RAM上であること。PCG反映は呼び出し側)
- IJ拡大/カーソルは `ntscv_ij_zoom` / `ntscv_ij_cursor_xor` 公開変数 (1バイト書込みはアトミック)

IchigoJam互換TVRAMレイアウト (shimが使用):

- IJTEXT: コード [0, 768) / 属性 [768, 1536) — 属性オフセット = 32×24 = 768
- カラー: コード [0, 1134) / 属性 [1134, 2268) (42×27)
- モノクロ80: コード [0, 2160) / 属性 [2160, 4320) (80×27)

## 5. ハードウェア資源と割込み

- PWM: 指定GPIOのスライス (チャネルA/Bはピン偶奇で自動選択)。CCレジスタ該当半分にDMA書込
- **DMA: 4チャネル リング、16ビット転送、1転送=2走査線 (1816サンプル)**。
  完了ごとに次チャネルへ相互chainで即再始動。各チャネルは4スロット
  (508µs) ごとに1度ストリームするため、バッファ再構築の期限は**508µs**。
  IJ合成 (~92µs) + WS2812送信の割込み禁止 (~31µs) が重なっても4倍以上の余裕
- **安全チャンク**: リング直後に「同期+黒」の有効2走査線分を配置。万一期限を
  超えてバッファ終端からはみ出して再生しても、白いゴミ (ガード値・隣接RAM)
  ではなく黒い2ラインとして出る
- **割込み内コード (ISR・チャンク組み立て・全レンダラ) はRAM配置**
  (`__not_in_flash_func` → 本memmapの `.time_critical` → .data)。XIPフラッシュの
  データ/コード参照も排除 (ドット幅テーブルはvolatileでRAM配置、
  割り算は起動時作成のRAM表 `ij_row_of_line` で置換)
- **バッファ永続化契約** (書込量を期限に余裕を持たせるための必須設計):
  - 有効映像ラインは内容部 (サンプル172-843) のみ書き換え、同期/ポーチ部と末尾は
    ブランキング領域の全書き込みの内容をフィールド中ずっと再利用する
  - 垂直同期はライン0-7、ブランキング前はライン10-17、有効映像直後はライン252-259
    (黒消去) のみ書き込み、残りラインは書き込まず各チャネルが4スロット前の
    自バッファ内容を再生する (アンカーは4チャネル分必要)
  - 停止中は一切書き込まない (直前のフィールドが静止画として出る)
- 割込み合流 (508µs以上の停止) が起きた場合: その時点でストリーミング中
  (BUSY) のチャネルは再構築を諦めて目標だけ進め、アイドルのチャネルは
  すべて再構築する → 垂直位相は保たれる (`ntscv_debug_events()` で監視)
- フラッシュ書込等で長時間割込み停止しても、DMAリングはSRAM上のバッファを
  再送出し続ける (画面は一時静止)。再開時は `ntscv_init()` で位相を再整合する
- 二重完了 (合流割込み) は1ライン分の更新を諦めて走査位相を2進めることで垂直位相を保持

## 6. 公開API

```c
void ntscv_init(uint8_t gpio);        // 出力開始 (157.5MHz設定済みであること)
void ntscv_release(void);              // DMA/PWM/IRQを完全解放 (SWITCH用)
void ntscv_stop(void);                 // 出力停止 (同期信号を消す — 旧stop_composite互換)
bool ntscv_active(void);              // 映像出力動作中
volatile uint16_t ntscv_frame_seq;    // フレームシーケンス (旧drawcount)
volatile uint8_t  ntscv_mode;         // 現在のモード (uint8書込みはアトミック)
void ntscv_set_line_hook(void (*cb)(void));
void ntscv_bind_text(uint8_t *codes, uint8_t *attrs, int cols, int rows);
void ntscv_bind_graph(uint8_t *vram);
void ntscv_bind_font(const uint8_t *font);
void ntscv_clear_text(void);          // バインド済みテキスト領域をゼロクリア
void ntscv_palette_set(uint16_t idx, uint8_t b, uint8_t r, uint8_t g);
void ntscv_test_pattern(int p);       // 0=通常, 1=カラーバー, 2=グリッド
uint16_t ntscv_debug_scanline(void);  // 診断: 現在の走査ライン
uint16_t ntscv_debug_events(void);    // 診断: 割込み合流回数 (通常0)
uint32_t ntscv_guard_a(void);         // 診断: DMAバッファ前ガード値
uint32_t ntscv_guard_b(void);         // 診断: DMAバッファ後ガード値
```

モード値: `NTSCV_MODE_IJ_TEXT`(6相当) / `NTSCV_MODE_COLOR_TEXT`(3相当) /
`NTSCV_MODE_COLOR_GRAPH`(18相当) / `NTSCV_MODE_MONO_TEXT`(5相当) —
shimの旧VMODE値と一致させる。

## 7. 検証計画

1. コンパイル時静的アサート: 908サンプル=63.42µs、262ライン ≒ 60.19Hz、バッファ境界整合
2. ビルド (cmake + arm-none-eabi-gcc) → UF2生成
3. 実機チェック (テレビの映像入力):
